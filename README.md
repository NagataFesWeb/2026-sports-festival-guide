# 体育祭サイト「長田すぎて滅！青春爆裂愛してる」

> 体育祭の公式情報サイト＋隠しカジノ風ベット機能

体育祭のプログラム・招集案内・（閉会式後の）総合順位をまとめて確認できる公式サイト。加えて遊び要素として、サイト内専用ポイントだけで遊べる「隠しカジノ」を搭載し、どの組が勝つかをベットして盛り上がれる（実際の金銭は一切使わない）。

## 主な機能
- **組み合わせ・プログラム表示** — 12 プログラムの時刻・場所・ルール・組み合わせを誰でも閲覧可能。実行委員が「進行の遅延・前倒し」で動かした時刻も反映
- **総合順位の表示** — 当日は非公開。閉会式で実行委員が1〜8組の最終順位を並べて確定・公開すると、入力した総合順位が出る。得点の入力・計算は行わない
- **招集案内検索** — 学籍番号を入力するとその人の出場競技（何の競技の何人目・第何走者か）・集合時間・場所・持ち物が表示（ログイン不要。友人の番号でも検索できる）。全種目の集合場所・招集隊形図も見られる
- **出場競技表** — 「誰がどの競技の何人目か」は `data/学籍番号別出場競技.csv` をビルド時に取り込んだ静的データから返すので、DB を経由せず即座に出る（更新のしかたは下記）
- **隠しカジノ（ベット機能）** — 隠しボタンから入場（口座作成時に好きなユーザーID・パスワード・ニックネームを登録）、サイト内ポイントで全体優勝／種目別勝者を予想（リレーは単勝・複勝・三連単、他は単勝のみ。騎馬戦は紅白2択。単勝・複勝は最低5倍、三連単は全組み合わせ50倍固定）
- **借金（クレジット）システム** — 「借りる」ボタンでポイントを借入れ（1回500ptまで、合計上限なし）、ベット結果発表ごとに借金額へ10%の利子
- **最終順位ランキング** — 体育祭終了後、純資産（所持ポイント−借金額）順の個人ランキングをニックネームで公開

> 各機能の受け入れ条件は [docs/spec.md](docs/spec.md)。

## 技術スタック
- **フロントエンド/バックエンド**: Next.js（App Router）
- **DB・認証**: Supabase（無料枠の Postgres + Auth）
- **デプロイ**: GitHub Pages（暫定的な静的案内版）／Vercel（全機能版、無料枠）
- **UI/演出**: Tailwind CSS（演出は CSS keyframes と WebAudio。外部の演出ライブラリは未導入）

全て無料枠で完結する構成。表画面「爆裂」（ポスター調。`docs/mockup/` のモック v2 が出典）と裏画面（カジノ）「古い賭博端末」で、配色・タイポグラフィ・演出を完全に切り替えたデザインにする（詳細は [docs/ui.md](docs/ui.md)）。

## セットアップ

Node.js 22 以降が必要。

```bash
npm install     # 依存のインストール
npm run dev     # 開発サーバー（http://localhost:3000）
npm test        # 単体テスト
npm run lint    # Lint と型チェック
npm run build   # 本番ビルド

npm run festival:sync # 管理用にDBを一度取得し、表画面の表示データを生成
```

環境変数を設定しなくても開発サーバーは動く。その場合データはサーバーのメモリ上（`.data/db.json` に保存）で、開発用のシードが入っている。

### 出場競技表（`data/学籍番号別出場競技.csv`）の更新

「自分の出場競技」は速さを優先して DB を使わず、CSV をビルド時に JS へ変換して同梱している。更新の手順は次の 3 つだけ。

1. `data/学籍番号別出場競技.csv` を新しいものに**同じファイル名で**差し替える（見出しは `学籍番号,出場競技`。1 人に複数競技があるときは全角の縦棒 `｜` で区切る。UTF-8 で保存し、値にカンマや引用符は入れない）
2. `npm run entries` で `src/lib/festival/entries.data.ts` を作り直す（`npm run dev` と `npm run build` の前に自動で走るので、普段は省略できる）
3. Supabaseへ接続した環境で `npm run entries:upload` を実行する。非公開Storageへ保存し、旧版はハッシュ名で退避する。保存後にサイトを再ビルド・デプロイする。CSVも生成物もGitHubへ送らない。

生成時はローカルCSVを優先します。CSVがないGitHub/Vercelのビルドでは、`NEXT_PUBLIC_SUPABASE_URL` とサーバー専用キーを使って非公開Storageから取得します。既定の保存先は `festival-private` バケットの `entries/2026.csv`。必要なら `FESTIVAL_ENTRIES_BUCKET` / `FESTIVAL_ENTRIES_OBJECT` で変更できます。Storageへの接続失敗・未配置は、空の出場案内を公開せずビルドを停止します。Supabase設定もCSVもない開発・CI環境だけは空データで動作します。[Supabaseの非公開バケット](https://supabase.com/docs/guides/storage/buckets/fundamentals)を使用し、匿名のCSV取得は許可しません。

見出しの間違い・学籍番号の重複・区切りが半角の `|` になっている・空の出場競技があるとビルドが止まって知らせる。`npm test` は CSV と生成物が一致しているかも確認するので、差し替えたのに生成し忘れた場合はテストが落ちる。

> `npm run dev` / `npm run build` は生成を自動で走らせるので、CSV を差し替えたあと起動すると `src/lib/festival/entries.data.ts` の差分が勝手に増える。CSVと生成物は個人情報を含むため、どちらもコミットしない。

反映の確認は `npm run entries` の出力にある人数・出場枠数・版番号で行えます。

### 当日の集合案内・3Dアニメーション

開催日は **2026年10月2日（金）**。8:15登校完了、8:20グラウンド集合、8:30点呼完了、8:45開会式、昼休み11:00〜12:00、閉会式14:20です。

トップまたは `/login` で学籍番号を入力すると、自分の競技と全員参加の案内が当日の順番に並びます。各カードで集合のタイミング・場所・出場枠・開始予定・持ち物を確認できます。実行委員が個人の集合案内を登録している場合は、その時刻と場所を優先します。

「集合場所を確認」は自分の生徒席から集合場所、競技位置への図。「競技の流れを見る」は集合→競技→交代→退場のアニメーションです。初期停止で、再生・一時停止・前後の場面を操作できます。速度・場面選択・回転・拡大縮小は折りたたみに入っています。GPSや3Dモデル保存の操作はありません。

リレー系は反時計回りに走ります。集合場所は「走前」、走り終えた後はゴール／バトン位置側の「走後」で退場の指示を待ちます。再生図にも両区分を表示します。

他の人の番号検索と全種目の閲覧は、下部の「ほかの人の案内を確認する」から開けます。配置・動線は概略です。台帳と競技順の食い違う集合タイミングは当日の放送・招集係に確認してください。資料と設定は [3D集合案内](docs/ground-guide/README.md)。

### GitHub Pages（暫定公開）

GitHub Pages 版はトップページ・プログラム・時刻表をビルド時の状態で公開します。個人検索フォームは無効になり、リアルタイム更新・カジノ・管理画面・APIは利用できません。全機能版はVercelへ配置してください。

### 本番（Supabase + Vercel）

サイト全体に `noindex, nofollow` を設定し、`robots.txt` でも全パスの巡回を拒否している。URL を知っている人は閲覧できるため、非公開データの保護には認証を使う。

1. Supabase でプロジェクトを作り、SQL Editor で `supabase/schema.sql` を実行する（列を足したときも同じファイルを再実行すればよい。`alter table ... add column if not exists` で既存データは保たれる）
2. Supabase Authentication の Site URL を本番 URL の `/admin/setup` に設定し、実行委員のメールアドレスを招待する。招待メールのリンクから本人が12文字以上のパスワードを設定する
3. `.env.example` を参考に、Vercel の環境変数に `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY` / `SESSION_SECRET`（16文字以上のランダム文字列）/ `ADMIN_EMAIL`（許可する管理者のメールアドレス）を設定する。`SUPABASE_SECRET_KEY` はサーバー専用で、ブラウザには渡さない
4. デプロイ後、`/admin` からチーム・種目を登録し、「CSV取り込み」で生徒名簿と招集案内を入れる

個別の出場表を使う場合は、上記の「出場競技表の更新」に従ってCSVを非公開Storageにアップロードしてください。今回の修正をデプロイすると、GitHub連携のビルドでも同じCSVを取り込めます。最新の確認状況は [当日の運用記録](docs/casino-operations.md) にまとめています。

本番ビルド（`NODE_ENV=production`）で Supabase の環境変数が無いと、起動時に例外で止まる（メモリ実装はサーバーレスでは再起動のたびに消えるため）。ローカルで本番ビルドをメモリ実装のまま試すときだけ `ALLOW_MEMORY_DB=1` を付ける。

> Supabase の無料プロジェクトは 1 週間使わないと一時停止する。体育祭の前日にダッシュボードから起こしておくこと。

## 使い方
- 一般生徒: トップページでプログラム・進行状況を確認 → 学籍番号を入力すると招集案内（出場競技・集合時間・場所・持ち物・招集隊形）を確認可能（ログイン不要）。総合順位は閉会式で公開される
- カジノ: サイト内の隠しボタンを見つけて押す → NEW ACCOUNT でユーザーID・パスワード・ニックネームを設定、以降は LOGIN でユーザーID＋パスワードを入力 → ポイントを賭ける。ユーザーIDは半角英数字・ハイフン・アンダースコアの4〜32文字で、大文字と小文字を区別する。パスワードは4〜32文字、ニックネームは1〜12文字。生徒名簿への登録は不要。足りなければ「借りる」で補充（1回500ptまで）、余裕があれば「返済」も可能。残高・借金・ベット履歴はカジノ内でのみ確認できる
- 実行委員: 管理者ログイン後、チーム・種目（ヒート＝学年別など）の登録 → Market の作成（ヒートごとに締切を設定） → 進行が遅れたら「進行」タブで時刻を動かす → 競技が終わったら「結果入力」で全競技で1〜8組を順位順に並べ替え、確認して確定（Market が精算されて配当と利子が付く） → 閉会式で「総合順位・優勝」を同じ方法で確定し、「順位公開」タブから公開 → 「最終精算」
- CSV の列: 生徒名簿は `学籍番号,名前,学年,組`（学年・組は任意）、招集案内は `学籍番号,種目名,集合時間,場所,補足`（補足は任意。「ゼッケン着用」など）。どちらも `/admin` の「CSV取り込み」からアップロードする
- 体育祭終了後: `/ranking` で純資産順の最終ランキングが公開される

### 開発時のカジノ確認
既存口座は以前の番号をユーザーIDとして同じパスワードで入場でき、残高・借金・ベット履歴を引き継ぐ。保存キー（`studentId` / DB列 `student_id`）は互換性のため維持しているが、カジノではユーザーIDを表す。順位表はニックネームとユーザーIDを表示し、ニックネームが未登録の旧口座はユーザーIDを表示する。

トップのロード演出は同じタブの初回だけ、充填0.6秒 → 100%の「爆裂」表示0.1秒 → フェード0.15秒の計約0.9秒。スキップも可能。ヒーローの登場はロード終了後、カードはスクロール時に再生する。左下の「演出 ON/OFF」で切り替えられ、選択は保存される。初期値はOSの動きを減らす設定に従う。

フッターの「実行委員 管理・結果入力」から管理者ログインへ進む。管理画面は結果入力が最初に開き、種目・学年を選ぶと8組の並べ替えだけを表示する。ドラッグ・↑↓・矢印キーで順位順に並べ、「順位を確認する」→「この順で確定する」。総合順位も同じ操作で入力し、得点は扱わない。

表画面（トップ・招集案内・最終順位）は表示時にDBへ接続しません。トップと最終順位は静的配信、招集案内は同梱の出場表・台帳・表示用スナップショットから返します。管理者の変更は再ビルド・再デプロイ後に反映されます。`npm run dev` / `npm run build` は管理用にDBを一度取得し、非公開順位・パスワード・生徒氏名を除いた `snapshot.data.ts` を生成します。設定済みDBへの取得失敗ではビルドを停止します。生成物はGitへ送りません。DB未設定の開発環境とtest/lint/Pagesは台帳の固定データを使い、架空の確定結果は公開しません。

カジノと管理者画面はDBに接続します。カジノの競技・履歴一覧で共通Market・種目・一覧集計用ベットを3秒だけサーバー内に保持し、同時取得をまとめます。書込み開始・終了でキャッシュを破棄します。残高・本人のベット・認証・受付と精算の検証はキャッシュしません。3D案内と開発用デモは開いたときだけ読み込みます。ローカルの速度確認には `npm run build` の後に `npm start` を使います。

`npm run dev` でトップとカジノの右下に「DEV / カジノ確認」を表示する。入場画面、開発用口座（2117 / 2117）での通常ログイン、起動・的中演出の再生、BGMの試聴ができる。口座がない環境では入場画面で認証する。本番ビルドには確認パネルを表示しない。BGM・効果音は初期OFFで、SOUNDスイッチから有効にする。
起動演出はモックv3のCLIログを液晶内で再生する。モニター枠と物理キーは起動・的中中も残り、起動は液晶クリックまたはENTER/BACKでスキップできる。入場済みでも `/casino/enter` を開くと起動・接続演出を再生してから競技一覧へ進む。


### 全区分の通しアニメーションとGitHub管理

3D案内の「競技の流れ」で、全12種目の集合・競技・交代・退場を確認できます。リレーは全学年・全組・第1走者から最終走者までを表示します。一時停止、0.5〜4倍速、場面選択、スライダーを使えます。初期状態は停止し、演出OFF・端末の「動きを減らす」設定でも「流れを再生」を押せば再生できます。動かさずに見る場合は、前後の場面を手動で切り替えます。

管理先は公開リポジトリ `NagataFesWeb/2026-sports-festival-guide`。名簿・個人別CSV・生成データ・原資料ZIP/Word・ローカルDB・環境変数は追跡しません。開発用名簿は「サンプル生徒」の架空データです。`npm test` / `npm run lint` も生成処理から実行するため、個人情報なしの新規チェックアウトでも動きます。

CSVもSupabase設定もない場合は空データを生成し、競技全体の案内を利用できます。ローカルのCSVは保持します。出場データはサイトの配信物に含まれるため、公開範囲は別途管理してください。

GitHub Actionsはpush／Pull Request時に、追跡禁止ファイル・秘密情報パターン、テスト、Lint、ビルドを検査します。手元でもGitに追加した後に `node scripts/check-repository.mjs` で検査できます（氏名や画像の人手確認も必要）。


### カジノの当日運営

画面を小さくし、同時ベット・再送・結果確定をまとめて保存する仕組みを追加しました。既存Supabaseには先に `supabase/casino-atomic.sql` を適用します。空のチーム・種目・Marketは `supabase/casino-day-setup.sql` で2026年10月2日の台帳から登録できます。

準備確認は `node scripts/check-casino-readiness.mjs`。前日準備、締切の設定、結果入力、障害時の対応は [当日運営手順](docs/casino-operations.md) を参照してください。本番のSQL適用と公開URLでの確認が完了するまでは受付を開始しないでください。

Supabase CLI 2.119.0を開発依存に追加しました。初回の `npm run db:login` 後、`npm run db:check` で接続確認、`npm run db:sql -- supabase/ファイル.sql` でSQLを実行できます。接続先は `.env.local` のURLを使います。カジノのSQLは接続先に適用済み（8チーム・12種目・14Market）。認証情報はGitへ保存しません。詳しいコマンドは [当日運営手順](docs/casino-operations.md) を参照してください。

### 動作検証で確定した結果を戻す

管理画面の「結果入力」で確定済みの競技を選び、「動作検証用：この結果をリセット」を開き、確認して実行する。配当と利子を確定前に戻し、ベットと口座は残す。対象口座が確定後に変わっていたら停止する。機能導入前の確定・最終精算後は対象外。締切は保持するため、ベットも試す場合はMarketタブで締切を変更する。表画面への反映は再デプロイが必要。
