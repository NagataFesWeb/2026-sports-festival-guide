## 1. 概要

- **一言コンセプト**: 体育祭の公式情報サイト＋サイト内ポイントだけで遊べる隠しカジノ風ベット機能
- **ターゲット**: 全校生徒（3学年・8チーム、招集案内は最大960人規模）＋実行委員（管理者）
- **チーム構成**: 学年をまたいだ色別対抗、全体で8チーム
- **チームカラー**: 1組 黄色、2組 水色、3組 白、4組 赤、5組 橙、6組 桃色、7組 緑、8組 青

> 詳しい背景は ../README.md（重複させない）。

### GitHub Pages 暫定公開

- GitHub PagesをActions方式で有効化した場合、`main`へのpushで静的案内版を公開する。未設定でも静的ビルドは検証し、Pages公開はスキップする
- 公開対象はトップページ、プログラム、時刻表。表示データはビルド時点のサンプル
- 個人検索、リアルタイム更新、カジノ、管理画面、API は GitHub Pages 版では操作不可と明示する
- 通常の Next.js／Vercel ビルドとサーバー機能は維持する

受け入れ条件:

- [x] `npm run build:pages` が `github-pages/out` を生成する
- [x] GitHub のリポジトリ名を `basePath` に設定しても、トップページの CSS・JavaScript・クライアント遷移が同じ配下を参照する
- [x] 静的版から未提供のサーバー機能へ入力・送信できない

### ✅ MVP

#### 機能1：組み合わせ・プログラム表示

- [x] 同じタブで初回のロード演出は約0.9秒（充填0.6秒・100%の「爆裂」保持0.1秒・フェード0.15秒）。スキップ可能で、再訪は待たずに開く。演出は常に有効。演出ON/OFFの切り替えボタンは表示せず、旧保存設定は使わない。
- [x] 元のHTMLのヒーロー登場・マーキー・スクロール登場を維持する。ヒーローの登場はロード終了後に開始し、画面外では継続アニメーションを停止する。

- [x] プログラムのカードを押すと詳細（ルール要約・対象・集合場所・持ち物・組み合わせ・ヒートごとの着順）がモーダルで開き、Esc／✕で閉じる

#### 機能2：競技結果・総合順位（順位だけで運用）

- [x] 騎馬戦以外の全競技（玉入れ・棒引きを含む）は、種目・学年を選び、1〜8組を上から順位順に並べ替える。得点入力・順位点の自動計算・合計集計は行わない。
- [x] 並べ替えはドラッグ（マウス・タッチ）・↑↓ボタン・つまみ上の矢印キーで操作できる。各組は必ず1回だけ表示し、空欄・重複を作らない。
- [x] 「順位を確認する」で8組の並びを確認し、「並べ替えに戻る」で入力を保持して戻れる。「この順で確定する」で保存する。確認チェックボックスや得点欄は出さない。
- [x] サーバーでも全組の欠落・重複・未知IDを拒否する。raceの下位順位を推測して配当計算に補わない。
- [x] 確定すると対応するMarketの配当・10%利子・結果を一度に保存する。同じ結果の再送では二重払いせず、配当後の順位変更を拒否する。
- [x] 総合順位は「総合順位・優勝」で別途1〜8組を並べ替えて確定する。競技の得点から推定しない。全体優勝Marketの `result_order` に全順位を保存し、先頭の組を勝者として精算する。
- [x] 未公開のトップはクラスの色と名前だけを表示する。「順位公開」で総合順位を公開すると入力した順序の1〜8位を表示し、得点は表示しない。総合順位未確定時の公開をサーバーでも拒否する。
- [x] 「非公開に戻す」で総合順位を隠せる。個人のポイントランキング（最終精算）とクラスの総合順位公開を分けて案内する。
- [x] フッターから管理画面へ進め、初期タブは結果入力。種目・学年ごとに1つのフォームだけを表示し、375px幅で横スクロールを出さない。

#### 機能3：学籍番号入力・マイページ（認証なし）
> 表側に「ログイン」は無い。学籍番号は本人確認ではなく**検索キー**で、他人の学籍番号を入れて他人の出場競技を見るのも想定内（友人の集合場所を確認する用途）。セッション・パスワード・DB 照合は行わない。カジノの認証（機能5）とは完全に別系統。

- [x] `/login` で学籍番号のみを入力すると `/me?id=<学籍番号>` に遷移する（名前・パスワードは求めない）
- [x] 学籍番号の形式が不正（空・数字以外）な場合は入力欄にエラーを表示して遷移しない。存在チェックは行わない（全角数字は半角に正規化）
- [x] `/me` には出場競技（機能4b）と招集案内（機能4）だけを表示する。ポイント残高・借金・ベット履歴はカジノ側（`/casino`）にのみ表示し、表側には一切出さない（カジノの存在を表側で露出させない）
- [x] `/me` の黒帯に学籍番号と、学年・組（学籍番号から導く）を表示する。名簿にあれば「2年1組・1組 黄色・サンプル生徒04」のようにチーム名と氏名も加わる

- [x] 学籍番号の出場競技・出場枠、集合タイミング・場所・持ち物、開始予定を同じカードにまとめ、プログラム順に表示する。重複する旧3一覧は表示しない。

#### 機能4b：出場競技表（DB不要の静的データ）

- [x] `data/学籍番号別出場競技.csv` を `npm run entries` で辞書化する。dev/build/test/lintの前に自動生成し、個人CSVと生成物はGit追跡しない。

- [x] 見出し・重複番号・形式・空欄・引用符・半角の区切りを検証する。枠のない行は警告し、空の枠として表示する。

#### 機能5：隠しカジノへの入場（カジノ独自の認証）
> 表側の学籍番号入力とは無関係。カジノ口座は `/casino/enter` で任意のユーザーID＋パスワードにより作成・認証し、入場後はサーバーが発行する署名付き Cookie セッションで本人を特定する。入場以外の Route Handler はこのセッションからユーザーIDを取り、リクエスト本文のIDは信用しない。

- [x] トップページのフッターの「79」を 1.4 秒以内に 5 回連続タップすると、`/casino/enter` の筐体に切り替わり、液晶内でモックv3と同一の19行のCLI起動ログを表示する。入力行は1文字/46ms、出力行は約7分割/18ms、初期待機1000ms。タップごとに文字色が変わる
- [x] 初回はユーザーID＋パスワード（新規設定）＋ニックネームを入力するとカジノ口座が作成され、`/casino` に入場する（初期ポイント1000pt付与）。生徒名簿との照合は不要
- [x] ユーザーIDは半角英数字・ハイフン・アンダースコアの4〜32文字（大文字・小文字を区別）。前後の空白は入場APIで除く。不正なIDは `INVALID USER ID`、使用済みIDは `ALREADY REGISTERED`。同時登録でも1口座だけ作られる
- [x] ニックネームは 1〜12 文字（前後の空白・改行・制御文字は不可）で必須。要件を満たさないと `INVALID NICKNAME` が表示され口座は作られない。重複は許可する（順位表ではユーザーIDも併記する）。作成後の変更機能は無い
- [x] 2回目以降はユーザーID＋パスワードの入力で `/casino` に入場できる。既存口座は以前の番号をユーザーIDとして使い、残高・ベット履歴を引き継ぐ
- [x] パスワードが誤っている場合はエラーが表示され入場できない（口座の有無は明かさない）
- [x] 未入場（セッション無し）の状態で `/casino` 配下や `/api/casino/*` にアクセスすると `/casino/enter` に誘導される（API は 401）

#### 機能7：借金（クレジット）・利子システム
- [x] `/casino` の F2 CREDIT（`/casino/credit`）に「借りる（ADVANCE）」があり、金額を指定してポイントを借入れできる（`points_balance` が加算され、同額が `debt_amount` にも加算される）
- [x] 1回の借入れ上限は500ptで、超える金額は借りられない（サーバー側で検証）
- [x] 借入れの合計上限（`debt_amount` の上限）は設けない
- [x] いずれかの Market が結果確定（`settled`）するたびに、その時点で `debt_amount` が0より大きい生徒全員に10%の利子が加算される（`debt_amount = debt_amount × 1.1`、端数切り捨て。計算方法は [data-model.md](data-model.md) を参照）
- [x] `/casino` 配下の全画面に現在の `points_balance` と `debt_amount` が常に表示される（表側の `/me` には表示しない）
- [x] 「返済（REPAY）」でいつでも任意の額を `points_balance` から `debt_amount` に充当できる（返済額は `points_balance` 以下かつ `debt_amount` 以下）。最終精算後は借入・返済とも拒否される

### 構成・設計判断（inline）

| 判断 | 選択 | 理由 | 代替 |
|---|---|---|---|
| DB・認証 | Supabase（Postgres + Auth、新形式の publishable / secret API キー） | 無料枠で完結し、生徒960人規模の読み取り・カジノの数十人同時アクセスに十分。DBを分ける必要がない | Firebase（Firestore は関係データ・集計が弱く、パリミュチュエル計算に不向き） |
| 認証の分離 | 表側は認証なし（学籍番号は検索キー）／カジノは任意のユーザーID＋パスワードの独自認証（署名付き Cookie セッション）／実行委員は Supabase Auth | 表側は「自分や友人の出場競技と場所を見る」用途。カジノはポイントを扱うため本人特定が必須で、生徒名簿とは独立したIDを使う。Supabase Auth は実行委員に使う | 表側も学籍番号＋名前でログイン（なりすまし防止にならず、手間だけ増える） |
| 永続化の抽象 | `src/lib/db/repository.ts` のインターフェース＋メモリ実装（開発）／Supabase 実装（本番、PostgREST を fetch で直接叩く） | Supabase の資格情報が無くても開発・テストが回る。`@supabase/supabase-js` を入れずに済み、依存追加の規約を守れる | supabase-js を依存に追加（便利だが規約上は要相談） |
| ポイント更新の整合性 | Route Handler で純粋関数が新残高を計算し、`updateBalances` の compare-and-set で書く（不一致なら最大 3 回やり直し） | Supabase の RPC（PL/pgSQL）に計算を二重実装すると TS 側のテストと乖離する。同時アクセスは数十人規模なので CAS で十分 | Postgres 関数で全計算（原子性は高いがロジックが二重になる） |
| 実行委員ログインの代替 | Supabase 未設定時は `ADMIN_EMAIL` / `ADMIN_PASSWORD`（開発時のみ既定 `admin@example.com` / `admin`） | Supabase 無しでも管理画面の動作確認ができる。本番でどちらも未設定ならログイン不可 | — |
| 演出ライブラリ | 未導入。CSS keyframes（`steps()`）＋ WebAudio のビープ＋ Canvas 2D（的中演出の紙吹雪を直接描く）で実装 | 裏画面は「古い賭博端末」の世界観なので、液晶上のリール回転とビープ音で十分に成立する。依存を増やさない | Framer Motion / GSAP / Lottie / canvas-confetti / Howler.js（AGENTS.md の構成案。必要になれば相談して追加） |
| ホスティング | Vercel（無料枠） | Next.js との相性・自動デプロイ | GitHub Pages（サーバー処理ができないため不可） |
| ベット方式 | 単勝は最低出場組数倍（8組なら8倍、紅白なら2倍）・複勝は最低出場組数÷3倍（8組なら8/3倍）のプール方式、三連単最低N×(N−1)×(N−2)倍（Nは出場組数、8組なら336倍） | 少人数参加でも払戻倍率を確保。全賭式の最低倍率を超える分はプールで計算 | 全賭式を純粋なプール方式にする |
| ポイント計算の実行場所 | サーバー側（Supabase RPC/Route Handler） | クライアント側計算だと生徒による不正なポイント操作を防げない | クライアント計算（不可） |
| 借金の管理方法 | `points_balance` と `debt_amount` を分離管理するクレジット方式 | 「借りる」操作を明示的な体験にでき、本場のカジノのマーカー方式に近い演出ができる | 残高一本化（シンプルだが「借りた」実感が薄い） |
| UI/アニメーション | CSS keyframes ＋ WebAudio（モック v2・v3 の `om-*` キーフレームを移植）＋ Canvas 2D（紙吹雪。canvas-confetti は入れずに直接描く）。外部ライブラリは未導入 | 表画面「爆裂」と裏画面「古い賭博端末」で世界観を完全に切り替える。モックの演出は CSS だけで成立しているため、依存を増やさない | Framer Motion＋GSAP＋Lottie＋canvas-confetti＋Howler.js（必要になれば相談して追加） |
| デザイントークン管理 | `project-design-system` スキルで表画面・カジノ画面それぞれの `DESIGN.md` を作成 | 2つの世界観を一貫性を保ちながら実装するため、色・フォント・モーションをトークン化して固定する | その都度スタイルを決め打ち（一貫性が崩れやすい） |
