## Supabase CLIでSQLを実行する

CLIはプロジェクトの開発依存としてバージョンを固定しています。`npm install` で入り、プロジェクト内で `npx supabase --version` を使えます。[公式の導入方法](https://supabase.com/docs/guides/local-development/cli/getting-started)に従っています。

```powershell
cd C:\Users\ryupc\WorkSpace\ngtHighSchool\2026-sports-festival-guide
npm run db:login
npm run db:check
npm run db:sql -- supabase/casino-status.sql
```

`db:login` のブラウザ認証はこの端末で完了済みです。別の端末では初回にログインしてください。CLIが保存する認証情報はAPI用のサーバーキーとは別で、チャットやGitへ貼る必要はありません。`db:check` は件数と保存処理の準備状態だけを読み取ります。`db:sql -- ファイル.sql` は指定したSQLファイルを実行します。

接続先は `.env.local` の `NEXT_PUBLIC_SUPABASE_URL` から取得します。Management API経由のSQL実行を使うため、DBパスワードやDockerの起動は不要です。当日の2本を順番に適用して状態確認するコマンドは `npm run db:apply-casino`。既に登録済みのMarketは保持します。

## 通信障害時

ベットと借入返済は15秒で待機を打ち切り、入力内容と再送識別子を保持します。再試行すると同じ操作として扱い、通信が切れる直前に保存済みでも二重に引いたり借りたりしません。送信結果が未確認の間は取消操作を止めます。同期中に返った古い残高で新しい操作結果を上書きしません。

取消はベット削除と返金を一度に保存するため二重返金しません。ログアウトに失敗した場合は画面に再試行案内を出し、ログアウトしたように見せません。共用端末はログアウト完了を確認して次の人に渡してください。
